# Pi: конфигурация этого Mac

Pi 1.5.0; Ghostty; основной режим — OpenAI Sol / high по подписке ChatGPT.
API-провайдеры выбираются явно, автоматического платного fallback нет.
Модели и effort при переносе не менялись. К исходному набору расширений добавлен
pi-bg-tasks для автоматического фона обычных команд.

## Что управляется Nix

[Модуль](../../modules/pi.nix) использует штатный Home Manager
`programs.pi-coding-agent` и официальный Nix-рецепт Pi. Исходники CLI закреплены
тегом `v1.5.0` и commit/hash в `flake.lock`; Node для CLI не зависит от mise.
У официального рецепта 1.5.0 пропущен override для pi-schema: в модуле есть
узкий workaround с хешем npm-архива 1.5.0. Удалить после исправления upstream.
В `postInstall` два косметических патча собранного CLI: меню `/` и `@` выводится
над полем ввода (строка ввода не прыгает), описания команд без меток
`[u:npm:pkg@версия]`. `--replace-fail` роняет сборку, если новая версия Pi
изменит эти места; тогда обнови или удали патч.

- `settings.json`: штатный `mutableSettings` Home Manager при активации
  вливает объявленные здесь ключи; остальные, включая deviceId и историю
  changelog, сохраняются. Пакеты сопоставляются по имени npm без версии,
  enabledModels заменяется целиком. Удаление декларации не удаляет старый
  ключ из существующего файла. Файл остаётся обычным, 0600: `/settings`,
  `/model`, `pi config` могут писать до следующей активации. Невалидный JSON
  останавливает активацию, а не сбрасывает конфигурацию.
- Общие правила (`AGENTS.md`), скиллы (`~/.agents/skills`) и MCP-серверы
  задаёт [`modules/agents.nix`](../../modules/agents.nix) для всех агентов.
  Раздел только для Pi лежит в `APPEND_SYSTEM.md`; `mcp.json` собирается из
  общего списка серверов плюс поля Pi (`exposure`, `description`) в `pi.nix`.
- Клавиши, модели, MCP, инструкции, профили, темы, локальные расширения,
  патчи и прочие конфиги — read-only ссылки Home Manager. Менять их следует
  здесь, а не командами, которые пытаются перезаписать эти файлы.
- STT получает абсолютные Nix-пути к ffmpeg/jq. Ключ читается из
  `auth.json` только при запросе диктовки, не копируется в конфиг или Nix store.
- Конфиг поиска доступен также через XDG `~/.config/pi/web-search.json`.
  Ponytail выключен по умолчанию.

**Не управляются и не публикуются:** auth.json, mcp-auth.json, trust.json,
sessions, models-store.json, install, npm/node_modules, кэши, backups,
session/project overrides субагентов.

## Первое применение и восстановление

1. Заверши все сессии Pi: активация конфигов и npm ci не должны конкурировать
   с работающими процессами.
2. Добавь новые файлы в Git перед обычной flake-сборкой — Git flakes не видят
   untracked-файлы. Выполни обычный rebuild из корня dotfiles.
3. Если Home Manager сообщает о существующем конфликтующем файле, перемести
   **только названный файл** в локальный backup и повтори rebuild. Не удаляй
   целиком `~/.pi/agent`; не перемещай auth/sessions. Автоматического force нет.
4. После активации выполни `pi-restore-extensions`. Команда восстанавливает
   npm manifest/lock, выполняет `npm ci --ignore-scripts --legacy-peer-deps`, затем явно запускает
   patch-package с ошибкой при несовместимости. Сеть нужна здесь, не во время
   Home Manager activation. Пакеты npm не являются частью Nix generations.
5. Проверь `type -a pi`: первой должна быть Nix-установка.
6. На новой машине выполни `/login openai`, при необходимости
   `/login openai-api`, `/login anthropic` и авторизацию MCP-серверов через `/mcp`.
   API-запросы, включая диктовку, оплачиваются отдельно.

Обычный rebuild не переустанавливает npm-пакеты. После изменения версий
повтори restore при закрытом Pi. Откат Nix не откатывает npm или авторизацию.

## Computer Use

codex-computer-use-mcp даёт Pi официальный runtime Computer Use из ChatGPT.app,
тот же `cua_repl`, через который работает Codex: окна читаются через дерево
Accessibility, действия идут виртуальным курсором в фоне, без вывода окна
вперёд. JS для `cua_repl` пишет текущая модель Pi. App-server ChatGPT пакет
запускает без модели и учётных данных, поэтому лимит подписки ChatGPT
не тратится.

- Нужен ChatGPT.app с компонентом Computer Use на аккаунте, где OpenAI
  включил unified runtime. После обновления ChatGPT открой его один раз,
  иначе пакет перейдёт на устаревшие инструменты; маршрут виден в
  `/computer-use-status`.
- Разрешения macOS Accessibility и Screen & System Audio Recording выдаются
  приложению **Codex Computer Use**.
- Подтверждений, allowlist приложений и фильтра опасных действий у адаптера
  нет. `ComputerUseAllowForbiddenTargets` не включаем: без него сервис не
  управляет самим ChatGPT.
- Пакет держится на экспериментальном API app-server, обновление ChatGPT
  может его сломать; диагностика в README пакета.
- AX-дерево и скриншоты попадают в контекст выбранного провайдера, через API
  это заметные токены. Не открывай секретные данные ради проверки подключения.

Начни с запроса: «Используй cua_repl: прочитай Finder и перечисли его окна,
ничего не нажимай».

## Подсказки следующего сообщения

next-prompt после каждого завершённого хода предлагает следующее сообщение
строкой под пустым редактором; → вставляет её без отправки. Настройки в
`next-prompt.json`.

- Подсказки делает Luna по API-ключу: доли цента за подсказку, лимит
  подписки ChatGPT не тратится.
- Для next-prompt это другой адрес, чем у активной модели, поэтому включён
  `allowCrossProvider`. Пары провайдеров OpenAI разрешены в конфиге без
  вопроса. Для остальных next-prompt спрашивает согласие на проект; ответ
  «всегда» в read-only конфиг не запишется, добавь пару в `next-prompt.json`.
- Режим widget по умолчанию не трогает редактор, который уже оборачивают
  pi-polish (маркер `❯`) и Nix-патч меню автодополнения; ghost поверх них
  не проверялся.
- Клавиша → вместо `Alt-/`: `alt-slash` занят AeroSpace.

## Единый UI

Все короткие меню и диалоги (ядро Pi, локальные extensions и npm-пакеты) рисуются
по одному образцу — родному стилю Pi, доведённому до единообразия:

```text
────────────────────────────────────────────   серая рамка (theme border)
 Tasks · 3 active                              заголовок: accent + bold, контекст muted, без двоеточия
 >                                             поиск, если есть
❯ ● agent · Проверка ядра   running            фокус ❯ (accent), текущее значение ✓
  ● bash · Long running     running
 enter open · escape/ctrl+c back               keyHint: клавиша dim, действие muted, « · »
────────────────────────────────────────────
```

- Один маркер фокуса `❯` вместо `→`, `›`, `▶`; `✓` — текущее значение или выбранная
  галочка (`[✓]` в мультивыборе). Акцентные рамки только у редактора (уровень thinking).
- Подсказки — последняя строка внутри рамки, имена реально назначенных клавиш в нижнем
  регистре (`enter`, `escape/ctrl+c`, `ctrl+s`); «back» для навигации, «cancel» для решений.
- Заголовки в sentence case: «Resume session», «Thinking level», «Fork from message».
  Экраны без заголовка (`/settings`) или без строки подсказок (`/fork`, `/logout`) их получают.
- `/resume`: одна строка заголовка (`Resume session · current folder`, справа фильтры
  name/sort), подсказки одной строкой снизу; на узком окне хвост подсказок отбрасывается,
  `back` остаётся. Подтверждение удаления и статус выводятся в этой же строке.
- Активность над редактором выровнена в одну колонку: `◆` монитор, `●` bash, `◈` агенты;
  активное состояние accent, время `1m 4s`. Сообщения interactive-shell в чате — одна строка
  (`◆ ticker · ready · READY 7`, `✓`/`✗`/`■`), Ctrl+O раскрывает полный текст.
- Реализация — `extensions/ui-polish.ts`: общие `titleLine`/`hintLine`/`focusMarker` для
  своих экранов (`/tasks`, `/files`) и presentation-патчи ядра. Экспортированные компоненты
  патчатся при старте сессии, неэкспортированные (trust, scoped models, MCP, config, setup,
  login menu, submenus) — при первом показе через `Container.addChild` по имени класса.
  Число строк и индексы детей сохраняются; пустые Spacer убираются только там, где мышь
  считает строки через Container. После обновления Pi повторить UI-проверки.

- Стоимость в footer: `~$0.30`, мелочь — `<$0.01`.
- Работающие bash-задачи показаны над редактором (поле ввода не прыгает): имя/ID, running, время,
  команда. До трёх строк, на низком терминале — только сводка; завершённые
  исчезают из активности, но остаются в чате и /bg-tasks.
- Мониторы interactive-shell и субагенты сохраняют собственные компактные
  виджеты. У субагента показана фактическая модель сессии (до старта — выбранная
  модель); effort и подробная статистика скрыты. Footer не повторяет счётчики
  агентов/bash; прочие статусы сохранены.
- Смена основной модели не скрывает уже понесённые API-расходы и не превращает
  историю подписки в API-расход. Расчёт использует provider/model из сообщений,
  usage-записей и дерева model_change для compaction/branch summary. Это оценка
  по текущему каталогу и типу авторизации провайдера, не исторический счёт:
  смена типа авторизации того же провайдера не восстанавливается, удалённые
  модели и старые записи без атрибуции не приписываются текущей модели.
  Для подписки и OpenAI API используются разные provider ID.
- Уведомления bash: ✓ успех, ✗ ошибка, ■ остановка. Ctrl+O раскрывает полное
  резюме, ID, путь к логу и уже сохранённый хвост вывода, не читая файл заново.
  Полный лог — через bg_output; путь/вывод могут содержать секреты.
- ask_user_question следует клавишам выбора Pi (включая Ctrl+J/K); Esc отменяет
  весь диалог, n — заметка к вопросу, Ctrl+] сворачивает диалог.
- `/tasks` объединяет навигацию, не менеджеры процессов: агенты открываются в
  существующем conversation viewer, PTY-сессии — через существующий attach,
  мониторы показывают состояние/события, bash — ограниченный хвост лога и exit code.
  Остановка требует подтверждения; Esc из просмотра не останавливает задачу.
  Просмотр лога не помечает результат доставленным и не подавляет wake-up агента.
  История ограничена временем жизни/retention каждого менеджера, не постоянная.
  Список/просмотр обновляются локально раз в секунду только пока открыты, без LLM.
- Виджет агентов показывает подсказку: при пустом редакторе ↓ выбирает агента,
  Enter открывает его диалог. Основной чат и footer сохранены.
- Локальный `ui-polish.ts` уплотняет штатный `/model` и простые селекторы/input,
  `/resume`, `/fork`, настройки, тему, effort, OAuth/login: убирает Spacer при рендере, не меняя
  индексы детей для обработчиков. Контейнер пересчитывает mouse layout.
  В `/model` показаны provider и фактический режим subscription/OAuth/API;
  поиск, scope, refresh и сохранение default остаются штатными. Это presentation
  patch приватных полей Pi 1.5.0; при несовместимой форме модельного selector
  используется штатный render. После обновления host повторить UI-проверки.
- `/tree` сохраняет штатное дерево/поиск/фильтры/метки и показывает короткую строку
  действий; подробная штатная справка раскрывается по F1. Общая рамка вложенных
  меню `/agents` уплотнена, основные Enter/Esc остаются видимыми.
- Полная карта поверхностей, фактическое покрытие тестами и оставшиеся расхождения:
  [UI-CHECKLIST.md](UI-CHECKLIST.md). Проверка компонента не заменяет ручной
  проход всего workflow; MCP manager и browser curator — отдельные UI, не общий select.
- Вопросы имеют высоту по содержимому без пустого хвоста после подсказок;
  подсказки короче, ожидание ответа обозначено отдельно от вычислительной работы.
- Интерфейс остаётся английским. В AGENTS.md закреплён русский язык **ответов
  агента**, включая вопросы и сообщения о ходе работы; отдельный i18n-пакет не нужен.

## Субагенты

Инструменты Lite (`Agent`, `StopAgent`, `MessageAgent`, `AgentStatus`) намеренно
без описаний и `promptSnippet`, поэтому в `<tools>` системного промпта Pi их нет.
Когда делегировать, модель узнаёт только из AGENTS.md и APPEND_SYSTEM.md (общее правило и раздел Pi)
и из `description` профилей, которые `exposeDescriptions` выводит в схему `Agent`.
Поэтому описания сформулированы как условия запуска. GPT без такой инструкции
сам не делегирует.

Дети на унаследованной модели запускаются без согласования: правят в тех же
границах, что и родитель, и не меняют оплату. Согласование нужно для API
(`haiku-*`) и смены модели, effort или режима оплаты. Explore получает `bash`
для истории Git; запрет на запись в нём задан инструкцией и не является sandbox.

## Фон без блокировки диалога

Два менеджера имеют разные задачи и идентификаторы:

- **pi-bg-tasks** владеет `bash`: короткие команды работают как раньше;
  в TUI через 120 секунд долгая команда уходит в фон. Заранее известные
  долгие команды агент запускает с `run_in_background: true`. Просмотр —
  `bg_list` / `bg_output`, остановка — `bg_stop`; завершение само будит агента.
  Ctrl+Shift+B не отбирает штатный Ctrl+B у редактора. Enter во время команды
  тоже переводит её в фон; Alt+Enter оставляет сообщение в follow-up очереди.
- **interactive-shell** доступен сразу (`defer: false`, схема `lean`):
  интерактивные CLI, мониторы логов/файлов/CI и конечные команды с жёстким
  лимитом времени. Уведомления ограничены 20 строками / 3000 символами;
  полный вывод доступен отдельно. Structured spawn по умолчанию использует
  отдельный worktree; это не разрешение самостоятельно запускать AI-агентов.

У `pi-bg-tasks` **bash.timeout — порог ухода в фон, не лимит жизни процесса**;
при `run_in_background: true` он не ограничивает длительность. В headless
режиме автоматический уход по таймеру выключен. Для жёсткого deadline агент
использует `interactive_shell`: `mode: "dispatch"`, `background: true`,
`timeout` в миллисекундах и `handsFree: { autoExitOnQuiet: false }`.
Тишина и `auto-close-quiet` не означают успех.

Мониторы запускаются с конкретными триггерами, дедупликацией, cooldown при
необходимости и конечным timeout. Между событиями модель не опрашивает статус.
Не смешивать идентификаторы `bg_*` и `interactive_shell` и не дублировать
одну команду в обоих менеджерах.

**Ограничения:** задания pi-bg-tasks не переживают `/reload`, выход или новую
сессию; логи временные и могут содержать секреты. Нет sandbox и гарантированной
доставки после падения Pi. Для окончательного вывода о тестах нужен фактический
exit code, не только уведомление «запущено». Сервисы/мониторы оставляются
работать после ответа только по запросу пользователя.

## Проверка лучших практик

Сверено с документацией Pi и публичными конфигурациями:
- [Pi configuration](https://pi.dev/docs/latest/configuration):
  настройки отдельно от auth/сессий; сохранён стандартный agent directory.
- [Pi packages](https://pi.dev/docs/latest/packages):
  точные версии, явные источники, патчи в Git.
- [Home Manager module](https://github.com/nix-community/home-manager/blob/master/modules/programs/pi-coding-agent.nix):
  штатный модуль вместо нового фреймворка конфигурации.
- [mikker/dotfiles](https://github.com/mikker/dotfiles/blob/02367074/pi/README.md)
  и [jinyeow/dotfiles](https://github.com/jinyeow/dotfiles/blob/main/pi/README.md):
  отдельно versioned non-secret config и runtime state.
- [Claude Code subagents](https://claude.com/blog/how-and-when-to-use-subagents-in-claude-code)
  и [Codex subagents](https://developers.openai.com/codex/concepts/subagents):
  условия делегирования; Codex делегирует только по просьбе или инструкции проекта.
- [Pi security](https://pi.dev/docs/latest/security):
  project trust оставлен ask. Инструкции в AGENTS.md, профили Explore и
  согласование субагентов **не являются sandbox или программным permission-gate**.
  Для недоверенного кода нужна изоляция ОС/VM/container.

Оставшиеся ограничения: Lite ограничивает concurrency на модель, а суммарный
потолок 4 и согласование запусков через API заданы инструкцией. max_turns 12 у
Haiku — мягкий предел, не денежный бюджет. Локальный патч Lite запрещает
подменять явно заданную, но отсутствующую в реестре модель родительской:
такой запуск завершается ошибкой. Наследование сохраняется при отсутствии
явного выбора. Overrides всё ещё имеют приоритет над профилем; перед запуском
нужно сверять их с согласованной моделью. Метаданные/тарифы в models.json —
снимок, не живой биллинг.
Локальные патчи повышают стоимость обслуживания; сохранены ради текущего UX.

## Проверки без запросов к моделям

Автоматизируем только проверки существенных поломок, которые дешевле
сопровождать, чем проверять вручную. Не тестируем внутренности сторонних
виджетов, точные подписи/число строк и значения настроек ради самих значений.

Из корня dotfiles:

```sh
mise run pi-check             # версии расширений; входит в общий lint
mise run pi-extensions-check  # после restore/обновления расширений; отдельно от lint
```

Пять файлов:
- `tests/settings.mjs`: согласованность версий settings/manifest/lock.
- `tests/extensions.mjs`: загрузка расширений, конфликты клавиш/команд,
  единственный владелец bash; расходы при смене модели родителя и накопительные
  расходы детей; отказ Agent при отсутствии явно выбранной модели.
- `tests/background.mjs`: реальные shell-процессы — успех/ошибка, доступный
  вывод, уведомление с wake-up, остановка и cleanup при reload.
- `tests/ui.mjs`: компактный model/effort selector, native выбор модели,
  светлая/тёмная тема и узкая ширина, отсутствие пустого хвоста вопросов,
  адаптер bash, безопасный вывод лога, выход из просмотра и подтверждение остановки;
  перевод всех форматов подсказок ядра в keyHint и однострочные сообщения interactive-shell.
- `tests/screens.mjs`: штатные экраны ядра на fixtures в sv-dark/sv-light при 40/80/120
  колонках; на каждом — единый стиль: нет `→`/`›`/`▶`, рамки цвета border, подсказки
  только в keyHint-формате; shutdown возвращает исходные методы.

Проверки расширений требуют установленных пакетов с текущими патчами.
По умолчанию они берут npm-модули из `~/.pi/agent/npm/node_modules`, а host —
из Nix-пакета `pi` в PATH (`tests/host.mjs`). Переопределения:
`PI_TEST_HOST_MODULES=<каталог-node_modules>` и `PI_TEST_NPM_MODULES=<каталог-node_modules>`.
Тесты не вызывают модели, не читают credentials и не включают микрофон.

Оформление проверяется вручную после UI-изменений: светлая/тёмная тема,
узкое окно, вопрос с отменой, ошибка инструмента и параллельные задачи.
Зелёный набор не означает полного тестирования Pi или всех расширений.
