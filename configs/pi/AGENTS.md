# Работа в Pi

По умолчанию отвечай пользователю на русском: пояснения, сообщения о ходе работы, итоговые ответы и вопросы. На другой язык переходи по явной просьбе пользователя. Код, команды, идентификаторы и цитаты сохраняй на языке исходника.

Сам выбирай подходящие инструменты и навыки для текущей задачи. Простые задачи выполняй сам; не запускай обязательный review loop.

## Фоновые команды и мониторы

Короткие неинтерактивные команды выполняй через bash. Заведомо долгие тесты и сборки запускай через bash с run_in_background: true, если можно продолжить другую работу или вернуть управление пользователю. Обычные команды в TUI автоматически уходят в фон через 120 секунд; Ctrl+Shift+B или /bg отправляет их в фон вручную. Параметр bash.timeout задаёт порог ухода в фон, а не жёсткий deadline; в headless-режиме автоматического ухода по таймеру нет. Для обязательного жёсткого лимита используй interactive_shell с mode: "dispatch", background: true, явным timeout (миллисекунды) и handsFree: { autoExitOnQuiet: false }.

Задания bash управляй через bg_list, bg_output и bg_stop. interactive_shell используй для интерактивных CLI и событийных мониторов: mode: "monitor", конкретные триггеры, разумный timeout, дедупликация и cooldown для шумных потоков. Для ожидания готовности или изменения CI используй monitor, а не длинный foreground poll-loop. Не запускай одну команду одновременно в двух менеджерах. Идентификаторы и команды управления у этих менеджеров разные.

После запуска фона или монитора продолжай независимую работу либо заканчивай ход и жди уведомления. Не используй sleep, периодические вызовы bg_output или опрос статуса только ради ожидания. При уведомлении проверяй exit code и фактический результат; тишина и auto-close-quiet не означают успешное завершение. Перед итоговым ответом дождись проверок, от которых зависит вывод. Останавливай ненужные серверы и мониторы; сохраняй долгоживущие процессы только по запросу пользователя. /reload и выход из Pi останавливают задания pi-bg-tasks; не перезагружай профиль посреди важной проверки.

Обычный shell-процесс или монитор не является AI-субагентом и сам по себе не требует согласования субагента; опасные команды, внешние побочные эффекты и запуск другого AI-агента требуют прежних согласований. Для AI-субагентов используй согласованный Agent/Explore, а не обход через shell.

## Субагенты и модели

Каждого субагента согласовывай с пользователем до запуска. Кратко предложи его задачу, зачем нужно делегирование, рабочую папку и границы правок, модель/провайдера, effort и режим оплаты (подписка или API). Дождись явного согласия на этого субагента; согласие на основную задачу или другого субагента не считается разрешением. Явная просьба пользователя запустить конкретного субагента уже считается согласием в указанных границах. Новый запуск, повторный запуск после завершения и новая задача существующему субагенту требуют нового согласования. Не обходи это правило запуском другого coding-agent CLI через shell. Держи не более четырёх активных субагентов суммарно. Это потолок, а не целевое число; делегируй только действительно независимую полезную работу. Квоты провайдера и ресурсы машины всё равно ограничены.

Используй Explore для исследования кода и general-purpose для самостоятельной части работы. Передавай цель, рабочую папку, границы изменений и ожидаемый результат. Не поручай двум агентам одновременно менять одни и те же файлы. Запускай согласованных детей в фоне; дожидайся уведомлений о завершении вместо опроса статуса, проверь и собери результат перед ответом.

Pi планируется основным harness для Codex по подписке ChatGPT и резервным для Claude через API, в том числе когда заканчиваются подписочные лимиты. Обычно пользователь работает в Claude Code по подписке и предпочитает Claude для программирования. Это предпочтение пользователя, не основание самостоятельно менять провайдера или оплату.

По умолчанию наследуй текущую модель вместе с провайдером и effort. Для сложной работы предпочитай Sol или Opus; для простых, чётко ограниченных и легко проверяемых подзадач можно предложить Luna или Haiku. Для coding-подзадач предпочтительный смешанный вариант — текущий Sol по подписке как ведущий и Haiku через API как исполнитель после отдельного согласования. Доступны haiku-explore (только чтение) и haiku-worker (небольшая правка), оба anthropic/claude-haiku-5-5, medium, мягкий предел 12 ходов. Обычные Explore/general-purpose по-прежнему наследуют родителя; не переводить всех детей на Haiku. Luna остаётся альтернативой для простой работы в рамках подписки, если доступна. Overrides модели в /agents могут перекрывать профиль; не запускай ребёнка при несовпадении с согласованной моделью. Передавай короткое самостоятельное задание, а не весь чат; результат проверь сам. Sonnet и Terra не выбирай автоматически и не предлагай как стандартный промежуточный уровень. Другую модель, effort или переход между подпиской и API применяй только после явного согласования; не подменяй согласованный вариант, если он недоступен. Исчерпание лимита не разрешает автоматический платный fallback.

Для структурированного выбора и согласования используй ask_user_question (до четырёх связанных вопросов в одном диалоге), когда инструмент доступен. Не спрашивай повторно о том, что пользователь уже явно разрешил. Отмена диалога не означает согласия; если инструменты недоступны, задай обычный вопрос в чате.
