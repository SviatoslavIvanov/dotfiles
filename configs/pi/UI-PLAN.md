# Pi: единый интерфейс и управление фоновой работой

Статус: реализованы локальные extensions и versioned патчи; единый стиль доведён до всех
поверхностей (README, «Единый UI»); установка ещё не активирована. Основание: предоставленный скриншот
вопросов, исходники установленного Pi 1.5.0 и расширений, текущие настройки.
Это аудит структуры по коду, а не визуальная приёмка всех экранов.
Полный реестр ядра, всех 12 npm-пакетов и локальных extensions, включая
остаточные расхождения и фактическое покрытие: [UI-CHECKLIST.md](UI-CHECKLIST.md).

## Что обнаружено

| Поверхность | Факт | Решение |
|---|---|---|
| Основной чат, редактор, footer | Уже есть sv-dark/sv-light и компактные рендереры | Сохранить, не добавлять постоянную боковую панель |
| `/model` | Отдельные строки Scope и подсказки, несколько Spacer, ID плюс имя модели, повтор имени под списком и статус обновления каталога | Уплотнить иерархию; избранные по умолчанию; технические подробности — только выбранной модели |
| Вопросы | `DialogView` выравнивает высоту по максимальной вкладке и дописывает остаточные пустые строки после footer | Убрать пустой хвост; отдельно проверить устойчивость высоты при смене вкладок и preview |
| Подсказки вопросов | Одна длинная строка, на скриншоте обрезается | Короткая адаптивная строка основных действий; дополнительные — по контексту |
| Агенты | Просмотр диалога, steering/continuation и остановка уже реализованы | Не писать второй viewer; сделать вход обнаруживаемым |
| Виджет агентов | В `subagents-lite.json` стоит `widgetNavHint: false` | Вернуть краткую подсказку; при пустом редакторе ↓ уже включает выбор, Enter открывает диалог |
| `/bg-tasks` | Сейчас вызывает `notify(formatJobList(...))`, а не интерактивный список | Добавить список с просмотром вывода и остановкой |
| Shell и мониторы | `/attach` уже выбирает сессию и открывает `ReattachOverlay`; default anchor — center, размер 95% × 60% | Переиспользовать подключение; унифицировать заголовок, статусы и доступ из списка задач |
| `/settings`, тема, effort | Штатные компоненты используют тему, но разную структуру и отступы | Общий ритм, маркер выделения и формат подсказок, без изменения логики настроек |
| `/resume`, `/tree` | Есть поиск/фильтры, собственные маркеры и насыщенные подсказки | Сохранить специализированную навигацию; `/resume` уплотнён, `/tree` получил компактный chrome и справку по F1; UI остаётся английским |
| Обычные select/input/confirm | Общие `extension-selector` / `extension-input` с рамками и Spacer | Исправлять общие компоненты, а не каждый вызывающий плагин |
| `/login`, доверие проекту | Общая тема, но отдельный layout и английский текст | Унифицировать осторожно; сохранить предупреждения, область действия и явные подтверждения |
| Файлы/diff, MCP, web curator, STT, computer-use confirmations | Есть дополнительные поверхности расширений | Все внесены в UI-CHECKLIST; MCP manager и browser curator не покрываются правкой общих selectors |

Источники для воспроизведения: `dist/modes/interactive/components/` установленного Pi;
`rpiv-ask-user-question/view/dialog-builder.ts` и `presentation.ts`;
`pi-subagents-lite/src/events.ts`, `src/ui/agent-widget.ts`, `src/ui/conversation-viewer.ts`;
`pi-bg-tasks/extensions/bg-tasks/ui.ts`; `pi-interactive-shell/index.ts` и `config.ts`.

## Общие правила

- Оставить Catppuccin Mocha/Latte и peach как акцент. Не перекрашивать всё выделение
  и заголовки в акцент одновременно. Основной текст — text, пояснения — muted.
- Один узнаваемый маркер фокуса `❯`, отдельная отметка текущего значения `✓`.
  Наведённое/выбранное в списке не означает уже применённое.
- Короткие выборы и вопросы — в нижней рабочей области рядом с местом ввода.
  Полноценный терминал, длинный диалог агента и дерево могут занимать большой экран:
  единый стиль не требует одинаковой геометрии у разных задач.
- Высота короткого диалога определяется содержимым, ограничена доступной областью.
  Не резервировать пустое место после последней подсказки. Не выталкивать действия
  за экран длинным вопросом, вводом или preview.
- Основные действия видны сразу; редкие детали раскрываются отдельно. Не прятать
  единственную подсказку о том, что строка вообще интерактивна.
- ↑↓ / Ctrl+J,K — выбор, Enter — открыть/применить, Esc — назад. Esc в viewer
  не останавливает задачу. Остановка — отдельное явно названное действие.
- Подсказки показывают реальные назначенные клавиши. Ввод текста не перехватывается
  глобальной навигацией; черновик и позиция списка сохраняются при возврате.
- Цвет не единственный индикатор: состояние сопровождается значком и текстом.

## Макеты структуры (фактический UI остаётся английским)

### Модели

```text
─ Модель · Избранные ─────────────────────────────────
  Поиск…
❯ ✓ Sol        ChatGPT · подписка       high
    Sol        OpenAI API · платно      high
    Opus       Anthropic API · платно   high

  ↑↓ выбор · Enter применить · Tab все · Esc назад
─────────────────────────────────────────────────────
```

Это схематичный фрагмент, не полный список настроенных моделей. Режим оплаты
определяется фактическим провайдером и типом авторизации, не именем модели.
ID/provider доступны в деталях и участвуют в поиске. Не смешивать одинаковые
модели по подписке и API. Смена сессионной модели и сохранение default — разные
действия. Каталог открывается из кэша; обновление не блокирует ввод и не сбрасывает
выделенную строку без необходимости. Ошибка обновления остаётся видимой.

### Вопрос

```text
─ Вопрос 1/2 · Объём работ ───────────────────────────
  Что меняем сначала?
❯ 1. Модели и вопросы
     Уплотнить меню и исправить нижнюю рабочую область.
  2. Также фоновые задачи
     Добавить общий список и доступ к деталям.
  3. Свой ответ…

  ↑↓ выбор · Enter ответить · Tab далее · Esc отменить
─────────────────────────────────────────────────────
```

Для мультивыбора явно показывать отметки и действие переключения. Подтверждение
нескольких вопросов сохраняется. Длинные описания переносятся; preview сравнения
остаётся доступен. Не уменьшать интерфейс ценой скрытых последствий выбора.
Ожидание ответа — «Нужен ответ», а не многоминутное «Running ask_user_question».
Длительность ожидания пользователя не выдаётся за активную вычислительную работу.

### Единая активность

Над редактором — несколько компактных строк и видимый вход `/tasks`.
Сам список открывается по команде; дополнительную клавишу выбрать после проверки
конфликтов. Существующие `/agents`, `/attach`, `/bg-tasks` сохранить.

```text
─ Задачи · 3 активны ─────────────────────────────────
❯ ● Агент     Проверка ядра        Sol       2м 14с
  ● Shell     dev server                    5м 03с
  ◉ Монитор   CI · ждёт события              1м 10с
  ✓ Bash      Проверка типов        exit 0      12с

  ↑↓ выбор · Enter открыть · Esc назад
─────────────────────────────────────────────────────
```

Действия зависят от типа:
- Агент: существующий live transcript, сообщение, результат, остановка.
  Продолжение завершённого агента — явный новый запуск, потенциально платный.
- Shell: подключиться к PTY через существующий механизм, вводить команды,
  отсоединиться без остановки; остановка отдельно.
- Монитор: состояние, последнее событие, история событий; подключение к терминалу,
  когда оно поддерживается конкретной сессией; остановка отдельно.
- Bash: ограниченный просмотр лога, exit code, путь к полному логу, остановка.
  Не обещать stdin/attach: этот менеджер не создаёт интерактивный терминал.

`/tasks` — общая UI-навигация, а не новый диспетчер процессов. Менеджеры остаются
владельцами запуска, cleanup и уведомлений; ID всегда сопровождается типом.
Нужен небольшой явный адаптер каждого менеджера, не парсинг текста уведомлений.
Открытие списка/лога не вызывает LLM. Просмотр обновляется локально, но не создаёт
опросов моделью или повторных уведомлений о завершении. Завершение задачи при
открытом viewer не должно менять выбранную строку на другую задачу.

## Русский язык — уточнение пользователя

Нужен русский язык ответов агента, а не локализация интерфейса. Правило добавлено
в AGENTS.md: пояснения, сообщения о ходе работы, итоги и вопросы по умолчанию
по-русски; другой язык — по явной просьбе. Код/команды/идентификаторы сохраняются.
UI остаётся английским, i18n-пакет и настройка языка интерфейса не добавляются.
Русские строки в макетах выше иллюстрируют структуру, не реализованный перевод.

## Порядок внедрения

1. Первый законченный проход: обнаруживаемость управления агентами, геометрия
   вопросов, адаптивные подсказки, явное состояние ожидания ответа, компактный `/model`.
2. Русский язык ответов через AGENTS.md; без перевода интерфейса (уточнено пользователем).
3. Интерактивный bash viewer и общий `/tasks` поверх существующих менеджеров.
4. Сквозная визуальная приёмка остальных экранов и устранение расхождений.

Правки хранить в dotfiles: настройки/локальные extensions и versioned npm-патчи.
Изменения core по возможности делать в общих компонентах, не плодить отдельную
реализацию каждого меню. Если потребуется расширить Nix-патчи, предпочесть
проверяемый патч исходников цепочке хрупких подстановок minified bundle.
Не менять установленные node_modules и не применять rebuild/npm ci внутри
работающих сессий Pi. Установка, активация и перезапуск — отдельный этап.

## Приёмка

- Тёмная и светлая тема; 80×24, 120×35, широкое окно; resize с открытым диалогом.
- Русские длинные строки, переносы, пустой поиск, ошибки, loading и отсутствие задач.
- Вопросы: 1–4 вкладки, разная высота, мультивыбор, preview, заметки, длинный свой
  ответ, сворачивание/возврат, отмена; клавиши и активный ввод всегда достижимы.
- Модели: различимы подписка/API, текущая модель и фокус; отмена ничего не меняет;
  default сохраняется только явно; refresh не ломает поиск и выделение.
- Все типы задач открываются без запроса к модели; просмотр не мешает завершению;
  Esc не убивает процесс, остановка не скрывает ошибку/exit code.
- Черновик редактора, фокус, scrollback и выбор восстанавливаются после возврата.
- Регрессии: существующие проверки settings/extensions/background; отдельные
  короткие проверки новой логики layout, адаптеров и маршрутизации действий.
- Ручной обход: `/model`, `/settings`, тема/effort, `/resume`, `/tree`, `/agents`,
  `/attach`, `/bg-tasks`, `/tasks`, вопросы, `/files`, MCP, web curator, STT,
  login/trust и computer-use confirmations (без запуска опасных действий).

## Внешние ориентиры

- [CLI Guidelines](https://clig.dev/): предсказуемые соглашения, обнаруживаемость,
  понятный выход и явные опасные действия.
- [NN/G: Consistency and Standards](https://www.nngroup.com/articles/consistency-and-standards/):
  одинаковые значения элементов и поведения внутри продукта.
- [NN/G: Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/):
  детали по запросу, но вход к ним виден.
- [NN/G: Recognition and Recall](https://www.nngroup.com/articles/recognition-and-recall/):
  контекстная подсказка вместо необходимости помнить скрытый жест.
- [Catppuccin style guide](https://github.com/catppuccin/catppuccin/blob/main/docs/style-guide.md):
  семантические роли цветов, спокойные поверхности, читаемость важнее палитры.
- [Claude Code interactive mode](https://code.claude.com/docs/en/interactive-mode):
  `/tasks` как доступ к фоновой работе; не путать с checklist, показываемым Ctrl+T.
- Локальная документация Pi: `docs/tui.md` — встроенные компоненты, keyboard-first,
  компактный вид с раскрытием деталей, правила ширины, focus и scrollback.

Привязка коротких вопросов к нижней рабочей области — проектное решение под этот
интерфейс и обратную связь пользователя, не универсальный закон TUI-дизайна.
