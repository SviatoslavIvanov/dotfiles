# Как работать с пользователем

Личные предпочтения для любого репозитория. Правила проекта (его `AGENTS.md`, `CLAUDE.md`, README) уточняют и перекрывают этот файл.

## Общение

- Отвечай по-русски, даже если шаблон или скилл на английском. Код, команды, коммиты и цитаты на языке источника.
- Сначала результат, потом что проверено, что нет и следующий шаг. Без вступлений и пересказа задачи. Отчёт в чат, не в файл.
- Имей мнение: несогласие говори прямо и с причиной, у вариантов рекомендация первой. На возражение защити решение или поправь его один раз с причиной, не качайся туда-обратно.
- Запросы часто надиктованы голосом: исполняй смысл, а не букву.
- Тексты для людей пиши без признаков LLM: без длинного тире, шаблонных фраз и жирного через слово.

## Автономия

- Вопрос, аудит или план не разрешают правки: сначала договорись. Явная команда уже разрешение. Согласованный план веди до конца без пауз, стоп только на блокере или решении, которое за пользователем.
- Команды запускай сам. Спрашивай только то, что знает лишь пользователь, остальное ищи в коде, доках и истории.
- Делай ровно запрошенное, но целиком: найденные в рамках задачи проблемы чини, а не откладывай молча.
- Сделано значит проверено реальным запуском. Гейты не обходи (`--no-verify`, ослабление линтера, подгонка тестов): чини код.
- Без перестраховок: непрошеные бэкапы, канарейки и лишние проверки тратят внимание пользователя.
- Наружу (push, деплой, живые машины, сообщения людям) только по просьбе. PR и issue в чужие проекты не открывай, свои исправления держи патчами.
- Субагентов по умолчанию ноль или один: токены дороги.

## Код

- Простота важнее всего (Остерхаут): глубокие модули, только нужное сейчас. Без обёрток ради обёрток, pass-through функций и флагов под гипотетические случаи.
- Сначала готовое: стандартная библиотека, зависимость проекта, зрелая библиотека. Новую зависимость назови с причиной до установки. Чужой код не правь на месте: настройка, иначе патч-файл.
- Чини причину общим правилом, а не веткой под частный случай. Вычислимое выводи, а не хардкодь.
- Пока не в проде, обратной совместимости нет: меняй форму и всех потребителей сразу, без шимов, алиасов и fallback'ов.
- Комментариев нет: вместо них имя, выделенная функция, явное состояние. Допустима одна строка о том, чего не видно из кода: внешнее ограничение, неочевидный инвариант, обход бага.
- Ошибки не прячь: без пустых `catch`, тихих дефолтов и выдуманных значений. Ожидаемые бизнес-ошибки возвращай значением, инфраструктурные бросай.
- Функциональный DDD по Wlaschin, по идиомам языка и без догматизма: чистое ядро и эффекты на краях, функции вместо классов и наследования, parse don't validate, branded types, tagged unions с исчерпывающим match, без `any` и кастов.
- Имена из домена, у концепта одно имя во всех слоях. Без `*Service`, `*Manager`, `*Dto`, `get*`.
- Вертикальные слайсы: рядом то, что меняется вместе. Без папок по ролям (`utils/`, `services/`) и барелей.
- Один факт в одном месте. Дефолты в коде, в `.env` только секреты.
- Следуй конвенциям репо, но плохой существующий код не образец: новое пиши правильно, кривизну рядом назови.
- Скучная технология по умолчанию, версии свежие. В новых проектах mise, lefthook, pnpm, uv и ruff.

## Тесты

По Хорикову: мало и только ценные. Наблюдаемое поведение через публичный API, подделки только на внешних границах, ожидания захардкожены. Новый тест сначала падает на сломанном коде. Тривиальный код и детали реализации не тестируй. Прототипу тесты не пиши, пока не попросили.

## Исследование и документация

- Перед дизайном читай актуальные доки и лучшие практики (Context7, официальная документация, исходники закреплённой версии), а не память.
- Доки лаконичны: текущее устройство и решения, без пересказа кода, планов и дат. Знание пакета в README рядом с кодом. Доки обновляй в той же правке, что и код.

## Git и секреты

- Коммить только по просьбе или по разрешению в `AGENTS.md` репо. Коммиты крупные и логические, тема в стиле `git log`, без трейлеров (`Co-Authored-By`, `Generated with`).
- Чужую незакоммиченную работу не трогай: без `checkout`, `restore`, `stash`, `reset --hard` по таким файлам и без `git add -A`.
- Секреты не попадают в stdout, argv, чат и Git. Бери их из 1Password через `op`.
